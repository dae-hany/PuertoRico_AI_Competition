# 전남대학교 강화학습 기말 프로젝트 설명 (2026)

> [English](COURSE_CNU_2026.md) | **한국어**
>
> 이 문서는 [COURSE_CNU_2026.md](COURSE_CNU_2026.md)를 한국어로 옮긴 번역본입니다.
> 두 문서의 내용이 서로 다르다면 영어 원문을 따릅니다.

2p 트랙은 전남대학교 인공지능학부 2026년 2학기 **강화학습** 수업의
**기말과제**이며, **개인** 과제입니다. 이 문서에는 일반 대회와 **다른 점만**
정리되어 있습니다. 그 밖의 모든 사항(엔진, 관측과 행동의 인코딩, **한 번의
행동 결정당 0.1초 제한**, 합법성 규칙, sandbox, 숨겨진 농장 타일 순서)은
[COMPETITION_RULES.md](COMPETITION_RULES.md)에 적혀 있으며, 수업에도 그대로
적용됩니다.

**두 문서의 내용이 충돌하면, 수업에서는 이 문서를 따릅니다.** (공개 IEEE CoG
에디션의 참가자는 COMPETITION_RULES.md만 따릅니다.)

| | 수업 (이 문서) | 공개 대회 |
|---|---|---|
| 트랙 | **2p만** | 2p와 3p |
| 순위 산정 | 학생 사이의 대전에서 거둔 **승수와 등수** (무승부는 0.5승) | Elo (2p) / TrueSkill (3p) |
| 제출물 | **zip 두 개**: 코드(에이전트 + README + 선택 사항인 weight 파일), 이어서 보고서 + 발표 자료 | 에이전트 파일 (+ 선택 사항인 weight 파일) |
| 래더 | 마감 전 중간 래더 **4회**, 승수와 등수만 공개 | 매주, 리더보드와 리플레이 공개 |
| 제출 경로 | **전남대학교 LMS** 과제 제출란 | 추후 공지 |

모든 시각은 한국 표준시(KST) 기준입니다.

## 성적

강화학습 최종 성적은 **기말시험 50% + 기말과제 40% + 출석 10%**로
구성됩니다. 기말과제 40%는 다음과 같이 둘로 나뉩니다.

| 항목 | 비중 | 평가 대상 |
|---|---:|---|
| 대전 결과 | **20%** | 학생 에이전트끼리의 대전(좌석 교대): **승수와 등수를 모두** 반영합니다 |
| 발표와 보고서 | **20%** | `presentation.pdf`와 `writeup.pdf`, 그리고 12월 3일 또는 5일에 진행하는 최종 발표 |

- **학생 에이전트끼리의 대전만** 성적에 반영합니다. 각 판은 승(1), 무(0.5),
  패(0)로 기록하며, 여러분의 **승수**는 이긴 판 수에 무승부 판 수의 절반을 더한
  값입니다.
- 함께 제공되는 baseline 에이전트와도 대전하지만, 그 결과는 **참고용으로 따로**
  공개합니다. 대전하는 baseline은 Random, Factory, ShippingRush,
  TradeBuilding, ActionValue, SearchLite, PPO이며, 이 중 PPO가 가장 강합니다
  ([아래](#방법은-자유이지만-rl을-권장합니다) 참고). 이 결과를 보고 자신의
  에이전트가 어느 수준인지 가늠할 수 있습니다.
- 승수와 등수를 점수에 반영하는 세부 방식은 **추후 공지**합니다.
- RL 사용 여부에 따른 **가감점은 없습니다**.

| 파일 | |
|---|---|

| `presentation.pdf` | 최종 발표(12월 3일 또는 5일)에 사용할 발표 자료입니다 |

### 별칭

클래스에 다른 사람과 구별되는 `name`을 지정하세요. 공개되는 리더보드에는 학번이
아니라 이 이름이 표시됩니다.

```python
class MyAgent(Agent):
    name = "Coffee Baron"       # your alias on the ladder
```

별칭은 다른 학생의 별칭이나 baseline 에이전트의 이름과 같으면 안 됩니다.
이름이 겹치면, 그 문제가 해결될 때까지 래더를 실행하지 않습니다.

## 실행 규칙

- **한 번의 행동 결정당 0.1초** (공개 대회와 같습니다). 이보다 오래 걸린 결정은
  **무작위 합법 행동**으로 대체됩니다. 평균 시간뿐 아니라, 가장 오래 걸리는
  상태(p95, 최댓값)에서도 여유를 남겨 두세요.
- **mask가 허용한** 행동을 반환해야 합니다. 불법 행동을 반환하거나 예외가
  발생한 경우에도 무작위 합법 행동으로 대체됩니다.
- **위반이 반복되면 실격 사유가 될 수 있습니다.**
- 시뮬레이션은 반드시 forward model의 **복사본**에서만 수행합니다.

  ```python
  sim = self.fm.clone()
  sim.step(a)
  ```

**금지:** 네트워크 접근, 하위 프로세스 실행, 파일 쓰기, 다른 참가자 코드 읽기,
실제 게임 상태 변경, 숨겨진 농장 타일 순서 읽기.

**허용:** **weight 파일 1개 읽기**(아래 설명 참고), 그리고 Python 표준
라이브러리, NumPy, PyTorch, 저장소 모듈 사용.

함께 제공되는 `Search`(1500 노드)와 `MCTS` 예제는 한 수에 0.1초보다 오래
걸립니다. 이 예제를 바탕으로 에이전트를 만든다면, 노드 수나 시뮬레이션 수를
줄이세요. (baseline 에이전트 자체는 원래 설계된 1초 예산을 그대로 사용하지만,
그 코드를 바탕으로 만든 참가 에이전트에는 1초 예산이 적용되지 않습니다.)

### weight 파일

수업은 공개 대회의 규칙([COMPETITION_RULES.md의 The weight file](COMPETITION_RULES.md#the-weight-file))을
따릅니다. 2026년 10월 20일부터 공개 대회도 수업에서 쓰던 규칙을 채택했으며,
여기에 용량 상한이 새로 추가되었습니다. 학습한 에이전트가 파라미터를 함께
제출할 수 있도록, **weight 파일은 정확히 하나만, 50 MB 이하로** 허용합니다.
weight 파일은 zip 안에서 에이전트 파일과 같은 위치에 두고, 작업 폴더가 아니라
**내 .py 파일의 위치를 기준으로** 불러오세요. 파일은 import 시점이나 생성자에서
읽어야 하며, `act` 안에서 읽으면 안 됩니다.

```python
import os
HERE = os.path.dirname(os.path.abspath(__file__))
state = torch.load(os.path.join(HERE, "weights.pt"), map_location="cpu")
```

채점기는 게임마다 에이전트를 새로 생성하므로, 파일을 한 번만 읽어서 모듈 수준
변수에 저장해 두고 재사용하세요(COMPETITION_RULES.md의 예시를 참고하세요).
이런 에이전트를 검사하면 `tools/validate_submission.py`가 파일 크기와 함께
**`[PASS] weight file`**을 출력합니다. 50 MB를 넘는 파일, 두 번째 파일, 작업
폴더 기준의 경로, 파일 쓰기는 **FAIL**이며, FAIL을 받은 엔트리는 해당 래더
라운드에서 제외됩니다.

## 방법은 자유이지만, RL을 권장합니다

휴리스틱, 탐색, 강화학습을 모두 사용할 수 있으며, 여러 방법을 결합해도
됩니다. 강화학습 수업이므로 **학습 요소**(가치 네트워크나 정책 네트워크,
self-play, 탐색 안에서 사용하는 학습한 가치 평가)를 넣기를 권장합니다. 다만
다른 방법을 사용해도 **불이익은 없으며**, 알고리즘 이름에 따라 점수를 주지도
않습니다.

학습을 마친 2p PPO 체크포인트(`training/checkpoints/ppo_baseline_2p.pt`)를
함께 제공하며, 이 체크포인트는 2p에서 가장 강한 기준선입니다. `Search`를
상대로 대략 세 판 중 두 판을 이깁니다. 이 체크포인트는 트레이너의 기본 설정으로
self-play만 수행해서 얻은 결과이며, CPU로 1.6시간이 걸렸습니다. 측정 수치와
학습 곡선은 [training/README.md](../training/README.md)에 정리되어 있습니다.
[`examples/ppo_entry/`](../examples/ppo_entry/)에는 이 체크포인트를 사용하는
완성된 엔트리가 제출 형식(`my_agent.py` + `weights.pt`) 그대로 들어 있습니다.
이 엔트리에서 출발해도 되지만, 보고서에는 **무엇을 왜 바꿨는지, 그리고 그
변경으로 성능이 얼마나 좋아졌는지**를 반드시 적어야 합니다. 기준선을 그대로
다시 제출한 엔트리는 보고서에 적을 내용이 없습니다. [README](../README.md)의
"Recommended approach" 절과 [SEARCH_BASELINE_2P.md](SEARCH_BASELINE_2P.md)도
참고하세요.

### 마감 전 중간 래더

- 각 회차에서는 **래더 당일 17:00까지** LMS에 제출한 학생끼리 대전합니다.
- **승수와 등수만** 공개합니다. 제출 코드와 리플레이는 **공개하지 않습니다**.
- 모든 상대 쌍은 공개 seed **1~25**를 사용하며, 각 seed에서 좌석을 바꿔 한
  번씩 대전합니다. 즉, **seed 25개 × 좌석 교대 = 상대마다 50판**입니다. seed는
  게임의 무작위 초기 설정을 고정하므로, 좌석을 바꾸면 두 사람 모두 같은 시작
  상태에서 양쪽 좌석을 한 번씩 플레이하게 됩니다.
- 래더 결과는 성적에 **반영하지 않습니다**. 다시 제출할 수 있으며, **마감 전
  마지막 제출본**으로 최종 평가합니다.

일찍 제출하면, 파일이 정상적으로 실행되고 형식이 올바른지 확인할 수 있습니다.
또한 아직 개선할 시간이 남아 있을 때 자신의 위치를 파악할 수 있습니다.

### 최종 채점

모든 상대 쌍은 **seed 500개 × 좌석 교대 = 상대마다 1000판**을 대전합니다.
seed 500개는 래더에 사용한 공개 seed 25개와, 공개하지 않는 **비공개 seed
475개**로 구성됩니다. 공개 seed에만 맞춘 개선은 최종 결과로 이어지지 않을 수
있습니다.

## 제출 전 검사

```bash
python tools/play.py --agent my_agent.py:MyAgent --games 20 --time-limit 0.1 --record
python tools/replay_game.py results/games/<game>.json --moves
python tools/validate_submission.py my_agent.py:MyAgent --track 2p --time-limit 0.1
```

`play.py`는 좌석을 바꿔 가며 대전합니다. `--vs all`을 지정하면 2p의 모든
baseline과 대전하며, `--games 20`은 빠른 확인용 예시일 뿐 통계적으로 충분한
판 수가 아닙니다. 검사 도구는 에이전트를 별도 프로세스(sandbox)에서 실행하여,
0.1초 제한으로 2판을 둡니다. 출력의 마지막 줄은 `Result: READY`여야 합니다.
FAIL은 모두 고치고, WARN도 모두 읽어 보세요.
