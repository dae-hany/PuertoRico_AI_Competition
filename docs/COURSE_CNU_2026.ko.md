# 수업 에디션: 전남대학교 강화학습 (2026)

> [English](COURSE_CNU_2026.md) | **한국어**
>
> 이 문서는 [COURSE_CNU_2026.md](COURSE_CNU_2026.md)를 한국어로 옮긴 번역본입니다.
> 두 문서의 내용이 서로 다르다면 영어 원문을 따릅니다.

2p 트랙은 전남대학교 인공지능학부 2026년 2학기 **강화학습** 수업의 **기말
프로젝트**이며, **개인** 과제입니다. 이 문서에는 일반 대회와 **다른 점만**
정리되어 있습니다. 그 밖의 모든 사항(엔진, 관측과 행동의 인코딩, **의사결정당
0.1초 제한**, 합법성 규칙, 샌드박스, 숨겨진 농장 타일 순서)은
[COMPETITION_RULES.md](COMPETITION_RULES.md)에 적혀 있으며, 수업에도 그대로
적용됩니다.

**두 문서의 내용이 충돌하면, 수업에서는 이 문서를 따릅니다.** (공개 IEEE CoG
에디션의 참가자는 COMPETITION_RULES.md만 따릅니다.)

| | 수업 (이 문서) | 공개 대회 |
|---|---|---|
| 트랙 | **2p만** | 2p와 3p |
| 순위 | 학생 사이의 대전에서 거둔 **승수와 순위** (무승부는 ½승) | Elo (2p) / TrueSkill (3p) |
| 가중치 파일 | **파일 하나 허용** (`weights.pt`) | 디스크 I/O 금지 |
| 제출물 | **zip 두 개**: 코드(에이전트 + README + 선택 사항인 가중치), 이어서 보고서 + 발표 자료 | 에이전트 파일 |
| 래더 | 마감 전 **4회**, 승수와 순위만 공개 | 매주, 순위표와 리플레이 공개 |
| 제출 경로 | **전남대학교 LMS** 과제 제출 페이지 | 추후 공지 |

모든 시각은 한국 표준시(KST) 기준입니다.

## 성적

수업 성적은 **기말고사 50% + 기말 프로젝트 40% + 출석 10%**로 구성됩니다.
기말 프로젝트의 40%는 다음과 같이 둘로 나뉩니다.

| 항목 | 비중 | 평가 대상 |
|---|---:|---|
| 대전 결과 | **20%** | 학생 에이전트 사이의 대전(자리를 바꿔 가며 진행): **승수와 순위를 모두** 반영합니다 |
| 발표와 보고서 | **20%** | `presentation.pdf`와 `writeup.pdf`, 그리고 12월 3일 또는 5일에 진행하는 기말 발표 |

- **학생 사이의 대전만** 성적에 반영합니다. 각 게임은 승(1), 무(½), 패(0)로
  기록하며, 여러분의 **승수**는 이긴 횟수에 무승부 횟수의 절반을 더한 값입니다.
- 함께 제공되는 베이스라인 에이전트와도 대전을 진행하지만, 그 결과는
  **참고용으로 따로** 공개합니다.
- 승수와 순위를 점수로 환산하는 방법은 **추후 공지**합니다.
- 강화학습을 사용했는지 여부에 따른 **가산점이나 감점은 없습니다**.

### 별칭

클래스에 다른 사람과 구별되는 `name`을 지정하세요. 공개되는 순위표에는 학번이
아니라 이 이름이 표시됩니다.

```python
class MyAgent(Agent):
    name = "Coffee Baron"       # your alias on the ladder
```

별칭은 다른 학생의 별칭이나 베이스라인 에이전트의 이름과 같으면 안 됩니다.
이름이 겹치면, 그 문제가 해결될 때까지 래더를 실행하지 않습니다.

## 실행 규칙

- **의사결정당 0.1초** (공개 대회와 같습니다). 이보다 오래 걸린 결정은
  **무작위의 합법 행동**으로 대체됩니다. 평균 시간뿐 아니라, 가장 오래 걸리는
  국면(p95, 최댓값)에서도 여유를 남겨 두세요.
- **마스크가 허용하는** 행동을 반환해야 합니다. 불법 행동을 반환하거나 예외가
  발생한 경우에도 무작위의 합법 행동으로 대체됩니다.
- **위반이 반복되면 실격 사유가 될 수 있습니다.**
- 시뮬레이션은 반드시 forward model의 **복사본**에서만 수행합니다.

  ```python
  sim = self.fm.clone()
  sim.step(a)
  ```

**금지 사항:** 네트워크 접근, 하위 프로세스 실행, 파일 쓰기, 다른 참가자의
코드 열람, 실제 게임 상태 변경, 숨겨진 농장 타일 순서 열람.

**허용 사항:** **가중치 파일 하나** 읽기(아래에 설명한 수업 예외), 그리고
Python 표준 라이브러리, NumPy, PyTorch, 이 저장소의 모듈 사용.

함께 제공되는 `Search`(1500 노드)와 `MCTS` 예제는 의사결정당 0.1초보다 오래
걸립니다. 이 예제를 바탕으로 에이전트를 만든다면, 노드 수나 시뮬레이션 횟수를
줄이세요. (베이스라인 에이전트 자체는 원래 설계된 1초 예산을 그대로 사용하지만,
그 코드를 바탕으로 만든 참가 에이전트에는 1초 예산이 적용되지 않습니다.)

### 가중치 파일 (수업 예외)

COMPETITION_RULES.md는 디스크 I/O를 금지합니다. 하지만 학습된 에이전트가
파라미터를 함께 제출할 수 있도록, **수업에서는 가중치 파일을 정확히 하나만
허용합니다**. 가중치 파일은 zip 안에서 에이전트 파일과 같은 위치에 두고, 현재
작업 디렉터리가 아니라 **에이전트 파일의 위치를 기준으로** 불러오세요.

```python
import os
HERE = os.path.dirname(os.path.abspath(__file__))
state = torch.load(os.path.join(HERE, "weights.pt"), map_location="cpu")
```

이런 에이전트를 검사하면 `tools/validate_submission.py`가 파일 접근에 관한
**WARN**을 출력합니다. 수업에서는 이 WARN이 정상적인 결과이지만, **FAIL**은
그렇지 않습니다.

## 방법은 자유이지만, 학습을 권장합니다

휴리스틱, 적대적 탐색, 강화학습을 모두 사용할 수 있으며, 여러 방법을 결합해도
됩니다. 강화학습 수업이므로 **학습된 구성 요소**(가치 네트워크나 정책 네트워크,
self-play, 탐색 안에서 사용하는 학습된 평가 함수)를 사용하기를 권장합니다. 다만
다른 방법을 사용해도 **불이익은 없으며**, 알고리즘의 이름만으로 점수를 주지도
않습니다. 함께 제공되는 PPO 체크포인트는 3p 트랙용입니다. 2p 학습은
`training/train_ppo.py --num_players 2`로 수행할 수 있습니다.
[README](../README.md)의 "Recommended approach" 절과
[SEARCH_BASELINE_2P.md](SEARCH_BASELINE_2P.md)를 참고하세요.

### 마감 전 래더

- 각 회차에서는 **그날 17:00까지** LMS에 제출된 코드끼리 대전합니다.
- **승수와 순위만** 공개합니다. 제출된 코드와 게임 리플레이는 **공개하지
  않습니다**.
- 모든 상대 쌍은 공개 시드 **1~25**를 사용하며, 각 시드에서 자리를 바꿔 한 번씩
  대전합니다. 즉, **시드 25개 × 자리 배치 2가지 = 상대 한 명당 50게임**입니다.
  시드는 게임의 무작위 초기 설정을 고정하므로, 자리를 바꾸면 두 사람 모두 같은
  시작 국면에서 양쪽 자리를 한 번씩 플레이하게 됩니다.
- 래더 결과는 성적에 **반영하지 않습니다**. 다시 제출할 수 있으며, **마감 전에
  마지막으로 제출한 코드**로 성적을 평가합니다.

일찍 제출하면, 파일이 정상적으로 실행되고 형식이 올바른지 확인할 수 있습니다.
또한 아직 개선할 시간이 남아 있을 때 자신의 위치를 파악할 수 있습니다.

### 최종 평가

모든 상대 쌍은 **시드 500개 × 자리 배치 2가지 = 상대 한 명당 1000게임**을
대전합니다. 시드 500개는 래더에 사용한 공개 시드 25개와, 공개하지 않는
**비공개 시드 475개**로 구성됩니다. 공개 시드에만 맞춘 개선은 최종 결과에서
효과가 없을 수도 있습니다.

## 제출 전 확인

```bash
python tools/play.py --agent my_agent.py:MyAgent --games 20 --time-limit 0.1 --record
python tools/replay_game.py results/games/<game>.json --moves
python tools/validate_submission.py my_agent.py:MyAgent --track 2p --time-limit 0.1
```

`play.py`는 자리를 번갈아 바꾸며 대전합니다. `--vs all`을 지정하면 모든 2p
베이스라인과 대전하며, `--games 20`은 빠르게 확인하기 위한 값일 뿐 통계적으로
충분한 게임 수는 아닙니다. 검증 도구는 에이전트를 별도의 프로세스(샌드박스)에서
실행하여, 0.1초 제한 아래에서 2게임을 진행합니다. 출력의 마지막 줄은
`Result: READY`여야 합니다. FAIL은 모두 수정하고, WARN은 모두 읽어 보세요.
